OVERALL VERDICT: The complete end-to-end flow does NOT work against the live PostgreSQL database.
The implementation logic is correct and all 78 automated tests pass using SQLite in-memory. However, the live PostgreSQL database schema is out of sync with the current models. Six columns added to evidence.py and fix.py were never migrated to the database, causing the entire investigation workflow to fail silently in the background thread, leaving bugs stuck in INVESTIGATING status permanently.

BUG #1 (CRITICAL): PostgreSQL schema out of sync with models — workflow fails silently

Symptom: After POST /api/bugs/<id>/start, the bug status stays permanently at INVESTIGATING. The background thread silently fails and never transitions the bug to WAITING_FOR_APPROVAL.

Root Cause: backend/models/evidence.py and backend/models/fix.py were modified to add new columns, but no database migration was run against the live PostgreSQL database. When the orchestrator attempts to INSERT into the evidence table, PostgreSQL rejects with:
psycopg.errors.UndefinedColumn: column "line_number_end" of relation "evidence" does not exist
Missing columns in PostgreSQL (vs. current models):
  • evidence table: line_number_end, search_query, relevance_explanation
  • fixes table: affected_lines, supporting_evidence_ids, confidence
Secondary symptom: The orchestrator's exception handler tries bug.status = BugStatus.FAILED; db.session.commit(), but this also fails because the DB session is in a broken transaction state (psycopg aborted transaction). The nested except catches this and calls db.session.rollback() which emits a SAWarning. Result: bug stays INVESTIGATING instead of FAILED.

Source files: backend/models/evidence.py, backend/models/fix.py, backend/core/workflow/orchestrator.py (exception handler)

Fix required: Run flask db migrate + flask db upgrade (or manually ALTER TABLE) to add the missing columns. No code change needed — models are correct.

11. Failures / Bugs Discovered

BUG #1 [CRITICAL] — PostgreSQL schema out of sync with models
Files: backend/models/evidence.py, backend/models/fix.py
DB table: evidence — missing columns: line_number_end, search_query, relevance_explanation
DB table: fixes — missing columns: affected_lines, supporting_evidence_ids, confidence
Impact: The entire investigation workflow fails. All live API calls to /api/investigations/<id>/evidence and /api/fixes/investigation/<id> return HTTP 500. Bugs stay permanently stuck in INVESTIGATING status.
Fix: Run flask db migrate -m "add missing evidence and fix columns" then flask db upgrade, OR manually: ALTER TABLE evidence ADD COLUMN line_number_end INTEGER; ALTER TABLE evidence ADD COLUMN search_query TEXT; ALTER TABLE evidence ADD COLUMN relevance_explanation TEXT; ALTER TABLE fixes ADD COLUMN affected_lines JSON; ALTER TABLE fixes ADD COLUMN supporting_evidence_ids JSON; ALTER TABLE fixes ADD COLUMN confidence FLOAT;
BUG #2 [MINOR] — Silent failure when orchestrator exception handler cannot commit
File: backend/core/workflow/orchestrator.py lines 327–333
Issue: The exception handler attempts bug.status = BugStatus.FAILED; db.session.commit() inside a nested try/except. When the outer exception leaves the session in a broken transaction, this commit also fails, the nested except calls db.session.rollback() (which emits a SAWarning), and the bug status remains stuck at INVESTIGATING instead of being set to FAILED. This makes diagnosing failed runs very difficult.
Recommended fix: Call db.session.rollback() first, then re-open a fresh commit to set the FAILED status.

12. Missing Functionality

  • No database migration infrastructure — the backend/database/migrations/ directory exists but contains only a .gitkeep. Flask-Migrate is wired up but no migrations have been created. Any model change requires a manual ALTER TABLE or the entire schema must be dropped and recreated.
  • No workspace/repos directory — target repositories (thefuck, tqdm, youtube-dl) are not cloned. The pipeline handles this gracefully but the end-to-end flow cannot collect real source-code evidence until repos are cloned.
  • No AI component configured — WATSONX_URL/PROJECT_ID are not set. The system correctly falls back to "[AI NOT CONFIGURED]" placeholders and machine-only evidence, but AI-assisted RCA and fix generation are unavailable.

13. Recommended Actions (Priority Order)

  1. [Critical] Apply the missing DB columns via ALTER TABLE (or recreate schema with flask db upgrade after generating migrations). This unblocks the entire live workflow.
  2. [Minor] Fix the exception handler in orchestrator.py to call db.session.rollback() before attempting a new commit to set FAILED status.
  3. [Enhancement] Create and commit an initial Flask-Migrate migration so future model changes are tracked and repeatable.
  4. [Enhancement] Clone at least one target repository to workspace/repos/ to enable full evidence collection in live testing.
